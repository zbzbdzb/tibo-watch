# Tibo Watch 0.2.16

本版集中修复 Chrome 监测页重复打开、采集仍有响应却被显示为数据超时，以及扩展实际运行版本不清楚的问题。桌面应用和 Chrome Companion 扩展均为 **0.2.16**。

## 主要修复

- 复用固定的“帖子”和“回复”监测页，切换焦点、唤醒扩展或恢复已有标签页时不再因为页面处于前台而另开一组。
- 长文补全复用后台监测页并恢复原地址，不再另开第三个详情页；前台页面不自动刷新、滚动或跳转。只清理归属明确且在后台的重复监测页，不关闭用户自有页面。
- 改进虚拟滚动、常驻加载提示和纯转发卡片下的采集就绪判断。纯转发仍不入库；仅有置顶帖不会被误认为完成整页采集。
- 将“同步中”“部分采集完成”“采集未完成”“数据已超时”和“需重新登录”分开显示。仍有报告但迟迟未完成两页采集时，明确显示采集未完成，而非把问题归结为连接或登录过期。
- 数据源详情显示实际运行的扩展版本、采集器修订号，以及每页的原因、报告时间、动态数、待补全文数和采样次数，便于区分旧脚本、加载未完成和真正的报告超时。
- 统一深浅色状态提示，并保留最近成功采集时间。

## 下载

- `Tibo-Watch-Setup-0.2.16.exe`：Windows 10/11 x64 安装包，支持覆盖安装。
- `Tibo-Watch-Chrome-Companion-0.2.16.zip`：同版本辅助扩展，先解压到长期保留的文件夹，再通过 Chrome 开发者模式加载。
- `SHA256SUMS.txt`：以上两个文件的 SHA-256 校验值。

安装包未进行代码签名，Windows 可能显示 SmartScreen 提示。

## 升级步骤及路径报错处理

1. 从托盘退出旧版 Tibo Watch，再运行安装包。本次不迁移数据库、不重算历史，保留现有记录、SMTP、收件人、公共 RSS 开关和其他设置。
2. 打开 `chrome://extensions`，重新加载 **Tibo Watch Chrome Companion**，确认卡片版本为 **0.2.16**。
3. 如果提示 `File path cannot be resolved` 或“无法加载清单”，说明需要检查原扩展目录是否还存在。更换安装目录后，Chrome 不会自动更新路径：取消错误提示，移除旧的辅助扩展，再选择当前安装位置中的 `resources\chrome-extension` 文件夹重新加载。可从应用“设置 → Chrome 登录共享 → 安装/打开扩展”定位该文件夹。
4. 回到应用“数据源”页，点击“立即检查全部”，查看实际收到的扩展版本及每页采集状态。若旧版遗留重复标签页，可手动关闭多余的一页。

加载时选择整个文件夹，不要选择单独的 `manifest.json`。常见目录为 `%LOCALAPPDATA%\Programs\Tibo Watch\resources\chrome-extension` 或 `C:\Program Files\Tibo Watch\resources\chrome-extension`，以实际安装位置为准。

Chrome 需要保持运行，且 X 页面可以正常读取。退出桌面应用后扩展不会继续创建或刷新监测页；仅关闭主窗口仍会保留托盘监测。页面读取可能受 X 页面结构、访问限制和网络状态影响，本次修复不保证所有页面异常都能自动恢复。

## 验证与隐私

- lint、TypeScript 类型检查及 **355 项单元/集成测试**通过。
- **19 项端到端测试**通过，覆盖打包 Electron 应用、隔离 Chromium MV3 扩展、多轮采集与焦点切换、长文补全和深浅色状态详情。
- 自动化浏览器回归使用独立临时配置和合成页面，不读取日常 Chrome 账号或登录数据；本机用户在安装并重新选择扩展目录后确认修复成功。

分类器与通知策略保持不变。“已确认重置”仅表示 Tibo 的公告被识别，不保证个人账号额度已经到账。本发行包不包含个人数据库、SMTP 凭据、收件人配置或浏览器登录信息；扩展不读取或导出 Cookie、密码或会话令牌。
