# Tibo Watch

Tibo Watch 是一个面向 Windows 10/11 x64 的本地桌面监测器。它每 5 分钟检查 `@thsottiaux` 的原创、回复和引用动态，判断是否出现 Codex 使用限制重置的确认、预告或相关信息，并通过 Windows 通知与可选 SMTP 邮件提醒。

> “已确认重置”仅表示 Tibo 已明确公告，不代表某个用户的个人 Codex 额度必然已经到账。

## 功能

- 公共 Nitter `with_replies` RSS：优先使用已验证实例和最后成功实例，失败后从公共注册表发现候选并自动切换；网络请求跟随 Windows 系统代理。
- 可选 Chrome 登录共享：辅助扩展复用当前 Chrome 的 X 登录状态，只读取页面可见动态，不复制 Cookie 或会话令牌。
- 四级本地规则分类：确认、预告、相关、无关；不调用外部 AI 模型。
- 首次同步只建立历史基线；按动态 ID 去重；预告升级为确认时可再次提醒。
- 默认确认/预告发送有声 Windows 通知和邮件，相关动态使用静默 Windows 通知；每类 Windows 通知均可独立开关、选择声音，修改即时保存且不影响邮件通知。
- SMTP 支持 STARTTLS/SSL、多收件人、测试邮件与 1/5/15 分钟持久化重试；连接按当前 Windows 系统代理策略建立，不需要关闭代理或填写固定代理端口。
- 单实例、关闭到托盘、Windows 开机静默自启；手动启动仍正常显示主窗口。
- 当前状态会自动刷新：确认重置显示 12 小时，预告显示 36 小时，到期后回到“监测中”，历史记录不受影响。

## 安装

从 [GitHub Releases](https://github.com/zbzbdzb/tibo-watch/releases/latest) 下载安装包，或从本地 `release` 目录运行：

```text
Tibo-Watch-Setup-0.2.21.exe
```

安装包为 per-user NSIS，无需管理员权限。首版未做代码签名，Windows SmartScreen 可能显示警告。卸载默认保留本地历史与配置。

## 首次使用

1. 启动应用并点击“建立历史基线并开始”。旧动态会入库，但不会补发通知。
2. 公共 RSS 默认启用；在“数据源”页检查健康状态。
3. 如需复用 Chrome 登录，在“数据源 → Chrome 登录共享”点击“安装 / 重载扩展”。
4. 如需邮件，在“通知 → 邮件提醒”填写 SMTP 主机、端口、用户名、应用密码、发件身份和收件地址，然后发送测试邮件。

### 首次安装 Chrome 辅助扩展

1. 点击“安装 / 重载扩展”；应用会打开 `chrome://extensions`、Tibo 监测页，并在资源管理器中选中扩展目录内的 `manifest.json`。
2. 在 Chrome 扩展页开启右上角“开发者模式”，点击“加载已解压的扩展程序”。
3. 选择包含该 `manifest.json` 的整个 `chrome-extension` 文件夹。
4. 保持 Tibo Watch 在托盘运行。扩展会自动创建或复用“帖子”和“回复”监测页；收到首批可见动态后，应用状态变为“已连接”。扩展会先确认桌面应用正在运行；从托盘“退出”应用后不会再创建或刷新监测页。仅关闭窗口会缩到托盘，后台监测仍会继续。

Chrome 要求用户亲自确认加载扩展，应用不会绕过这一步。扩展 ID 固定为 `cnhojdncaimngpikaokmgpnihhglnmkn`。

### 升级后重新加载扩展

桌面应用当前为 **0.2.21**，辅助扩展仍为 **0.2.16**。本次未修改扩展，从 0.2.16 升级且安装目录不变时无需重载。如需重载，在 Chrome 地址栏输入 `chrome://extensions`，找到 **Tibo Watch Chrome Companion**，点击该卡片上的圆形箭头“重新加载”（必要时先开启开发者模式）。安装目录没有改变时，无需移除后重装。

如果提示 `File path cannot be resolved` 或“无法加载清单”，请检查是否更换过应用安装目录。Chrome 的重新加载仍然使用旧路径，不会自动寻找新版目录：

1. 取消错误提示，移除旧的 **Tibo Watch Chrome Companion** 扩展。
2. 在应用“数据源 → Chrome 登录共享”点击“安装 / 重载扩展”，定位当前安装位置中的 `resources\chrome-extension` 文件夹。
3. 在 Chrome 点击“加载未打包的扩展程序”（部分版本称“加载已解压的扩展程序”），选择包含 `manifest.json` 的整个文件夹，不是单独的清单文件。
4. 确认扩展卡片显示 **0.2.16**，回到应用“数据源”页点击“检查全部来源”。

常见扩展目录为 `%LOCALAPPDATA%\Programs\Tibo Watch\resources\chrome-extension` 或 `C:\Program Files\Tibo Watch\resources\chrome-extension`，请以当前实际安装位置为准。也可下载本版扩展 ZIP，解压到长期保留的目录后加载，后续在同一目录更新文件并重新加载扩展。

新版扩展会触发一次采集，桌面应用收到报告后即时更新状态。“数据源”页显示实际运行的扩展版本、采集器修订号、帖子/回复各自的采集原因与报告时间。磁盘文件更新不代表后台脚本已重载；“需重载扩展”表示仍收到旧协议或旧采集器报告。“等待扩展”或“采集未完成”不等于需要反复重载，应根据每页原因检查应用是否暂停、X 页面能否正常显示，以及登录是否有效。

## SMTP 常见配置

数据源、通知开关、声音、检查间隔和启动设置均单独即时保存。SMTP 使用独立的“保存邮件配置”；取消不保存，密码留空保留原密码。收件人在“通知 → 邮件提醒”中添加或移除并立即保存。发送测试邮件只使用已保存配置，不会自动提交草稿。

通知记录区分等待、发送中、部分失败、SMTP 已接受和取消。按收件人重试，已接受的地址不会因另一地址失败而被重复发送。SMTP 接受不保证已进入收件箱；服务器接受后立即断电存在结果不确定的窗口，重试沿用相同 Message-ID，但无法保证邮件端严格仅一次。

优先使用邮箱服务商生成的“应用密码”，不要填写主账号密码。

| 类型 | 常见端口 | 加密方式 |
| --- | ---: | --- |
| Gmail SMTP | 587 | STARTTLS |
| Gmail SMTP | 465 | SSL/TLS |
| Microsoft 365 SMTP 提交 | 587 | STARTTLS |
| 其他服务商 | 以服务商文档为准 | STARTTLS 或 SSL/TLS |

若测试失败，请依次检查：应用密码是否启用、SMTP 主机和端口、发件身份是否允许、VPN/防火墙、服务商是否禁用了基础 SMTP 验证。日志和界面不会输出应用密码。

## 数据、备份与隐私

默认数据目录：

```text
%APPDATA%\tibo-watch\
```

- `tibo-watch.sqlite3`：动态、分类、来源观测、通知送达、邮件队列和设置。
- Chrome 登录信息始终保留在 Chrome 自己的配置中；Tibo Watch 不创建或备份 X 登录分区。
- SMTP 应用密码先经 Electron `safeStorage`（Windows DPAPI）加密，再存入 SQLite。

备份时先从托盘退出 Tibo Watch，再复制整个目录。恢复时同样先退出应用，然后覆盖回原位置。详细说明见 [PRIVACY.md](PRIVACY.md)。

## 风险说明

X 明确限制非 API 的网站脚本化访问。启用 Chrome 登录共享仍可能导致会话失效、访问受限，极端情况下可能影响账号；该功能可随时禁用。公共 Nitter 实例是非官方第三方服务，可能随时不可用或延迟。两路数据连续三个周期均失败时，应用只提示一次监测中断。

应用不读取个人 Codex 配额，不包含 VPN，不提供公网服务，不自动上传历史，不集成外部模型，也不包含自动更新。

## 0.2.20 邮件代理连接修复

- SMTP 每次连接重新解析 Windows 系统代理/PAC 策略，支持 HTTP/HTTPS CONNECT 和免认证 SOCKS5，不写死本地代理端口。没有代理时按系统 DIRECT 策略直连；代理失败不会自行添加直连回退。
- 保留端到端 SSL/TLS、强制 STARTTLS 和证书验证；不复用浏览器 Cookie，也不把 SMTP 应用密码当作代理认证密码。
- 邮件提示和送达记录区分代理失败、连接超时、服务器响应超时、账号验证失败，旧 `ETIMEDOUT` 记录也有中文说明。
- 不改变 SMTP、收件人、通知去重、分类器与历史数据；不自动批量重试终止的旧邮件。仍在队列中的邮件沿用既有重试规则。

## 0.2.19 重置识别与界面精简

- 本地规则升级到 `rules-v9`，将重置谓词解析独立出来：支持省略助动词的完成公告、完成/进行语态的修饰词，以及午夜、中午、24 小时时间和与未来动作绑定的 today；不会仅凭 today 或其他句子的上线时间升级。
- 保留主文/引用、动作对象、否定、疑问和推测边界。同一条内完成优先于后续计划，证据仅保留获胜动作附近的内容。
- 启动时按新版本和完整正文哈希重算历史；过期历史静默修正，12 小时内确认、36 小时内预告沿用每条/级别去重。重复抓取不重复分类，截断正文不覆盖完整正文。
- 删除总览、收件箱、数据源及通知页七处装饰性文案；通知开关、发送记录、错误说明和来源诊断保留。
- 不修改 Chrome 扩展、SMTP、收件人、数据库结构或静默启动设置。

## 0.2.18 桌面界面更新

- 落地已确认的浏览器原型：顶部五页导航，独立动态收件箱，列表与正文分别滚动，筛选、刷新和阅读操作固定可见。
- 删除收藏、拆词证据、识别教学和隐私宣传卡片；保留完整正文、引用、简短判断说明和真实逐渠道送达记录。

## 0.2.17 公共 RSS 可用性修复

- 加入 2026-09-12 实测可读取目标账号帖子、回复及引用的 `https://nitter.perennialte.ch`。先尝试最后成功实例及内置优先实例，再查询公共注册表，避免注册表故障拖累可用订阅。
- RSS 和注册表请求改用 Electron 网络层，自动遵循 Windows 系统代理及 PAC；没有系统代理时仍直连，不内置代理服务、不写死代理端口。
- 使用独立内存网络分区，不带 Cookie、不复用 Chrome 登录、不缓存响应或跟随重定向；关闭 RSS 后不初始化该分区或发起新的 RSS 请求。
- 注册表仅采纳公共表格中同时在线、工作正常的 HTTPS 实例，不把状态网站或证书检测网站当作 RSS 源。临时注册表失败可在后续检查中重试，HTML 验证页和无效 XML 不算采集成功。
- 保留 RSS 开关、历史数据库、SMTP 和其他配置；已经关闭 RSS 的用户升级后仍保持关闭，可按需在数据源中启用。公共实例可用性无法长期保证，Chrome 监测不受此变更影响。

## 开发

要求 Node.js 22.16+、pnpm 11 和 Windows x64。

```powershell
pnpm install
pnpm dev
```

验收命令：

`test:e2e` 同时包含 Electron 界面测试与隔离 Chromium 扩展的真实 HTTP 握手回归。首次运行请使用 `pnpm exec playwright install chromium` 安装测试浏览器；也可用 `TIBO_WATCH_CHROMIUM` 指定已有兼容 Chromium 的可执行文件。测试创建独立临时用户目录，只连接测试回环服务，不读取日常 Chrome 配置或登录信息。

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm build
pnpm dist:win
```

项目结构：

```text
src/main       Electron 主进程、监测、SQLite、通知
src/preload    受限 contextBridge API
src/renderer   React 界面
src/shared     稳定领域接口和 IPC 类型
tests          单元、集成与 Electron E2E
```

## 安全边界

- 渲染器启用 CSP、上下文隔离和沙箱，不启用 Node 集成。
- 所有 IPC 调用校验发送方和 Zod 参数。
- Chrome 辅助扩展仅有 X 页面、标签页、脚本注入和本机 `127.0.0.1:47652` 权限。
- 本机桥接对动态提交校验固定扩展来源与标识，限制请求体大小并使用 Zod 校验动态字段。只读健康探测兼容 Chrome 不发送 `Origin` 的 GET 请求，仍要求指定扩展标识；不返回动态、设置或凭据，也不对无来源探测授予 CORS 权限。
- 外链仅允许打开 `@thsottiaux` 的 X/Twitter 动态 URL。
